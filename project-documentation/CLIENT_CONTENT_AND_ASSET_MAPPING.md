## Section 10: Cloudinary Integration Status

### Current Upload Architecture

**Status: ❌ CLOUDINARY NOT INTEGRATED**

| Component | Current State |
|---|---|
| `backend/package.json` | No `cloudinary` or `@cloudinary/node-http-proxy` dependency |
| `backend/src/middleware/upload.middleware.js` | Uses **Multer disk storage** only — files saved to local `uploads/` directory |
| `backend/src/config/env.js` | No Cloudinary env vars defined or exported |
| `backend/.env.example` | No Cloudinary credentials mentioned |
| Upload URL storage | Relative paths like `/uploads/gallery/xxx.jpg` stored in DB |
| File deletion | `deleteLocalFile()` in controllers deletes from disk |
| Cloud storage | None — Render's ephemeral filesystem used |

### Critical Risk

> **Every time the Render service restarts or redeploys, ALL uploaded files (gallery images, documents, logos, director photo) are PERMANENTLY DELETED.** The database still holds the URLs but the files no longer exist. This will cause broken images across the entire website.

### Files Requiring Modification for Cloudinary

| File | Required Change |
|---|---|
| `backend/package.json` | Add: `cloudinary`, `multer-storage-cloudinary` |
| `backend/src/config/env.js` | Export: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` |
| `backend/.env` / `.env.example` | Add Cloudinary credentials |
| `backend/src/middleware/upload.middleware.js` | Replace `multer.diskStorage()` with `CloudinaryStorage` from `multer-storage-cloudinary` |
| `backend/src/controllers/gallery.controller.js` | Replace `deleteLocalFile()` with Cloudinary `destroy(public_id)` |
| `backend/src/controllers/settings.controller.js` | Same — replace local file delete with Cloudinary destroy |
| `backend/src/controllers/news.controller.js` | Same |
| `backend/src/controllers/document.controller.js` | Same |

### Required Environment Variables

```env
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
```

> ⚠️ These credentials must ONLY be in `backend/.env` (server-side). Never expose in frontend code, `NEXT_PUBLIC_` vars, or client-side bundles.

### Cloudinary Integration Plan (Do NOT implement until instructed)

1. Create a free Cloudinary account (tilakglobalschool or developer account)
2. Install: `npm install cloudinary multer-storage-cloudinary`
3. Create `backend/src/config/cloudinary.js` — configure v2 SDK
4. Update `upload.middleware.js` — use `CloudinaryStorage` per subfolder with auto format and quality settings
5. Store Cloudinary `public_id` in DB alongside URL for deletion capability
6. Update all 4 controllers (gallery, settings, news, documents) to use `cloudinary.uploader.destroy(public_id)` on delete
7. Configure transformations: `quality: 'auto'`, `fetch_format: 'auto'`, `width: 1920` for images
8. Test upload → view → delete cycle end-to-end
9. Migrate existing uploads if any (unlikely given ephemeral storage issue)
